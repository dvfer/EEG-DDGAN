## Why

Synthetic EEG generated by `TTSGenerator` (rama `ttsgan-direct`) contains high-frequency energy that real BNCI2014_009 P300 trials never have — MOABB's `P300()` paradigm bandpass-filters real data to `[1, 24]` Hz, so any synthetic content above ~24 Hz is artifact, not signal. The root cause is patch-boundary seam discontinuity: the generator reconstructs the raw sequence from non-overlapping transformer patches, and nothing smooths the seams afterward. The previous (`main`-branch) autoencoder-coupled pipeline suppressed this incidentally — the frozen AE decoder, trained only on real reconstructions, implicitly smoothed the seams before the signal reached the discriminator — but `ttsgan-native-multichannel` deliberately removed that coupling because it forced every discriminator step to decode fake latents through the AE just to feed the DWT discriminator raw samples. Post-hoc low-pass filtering the generator's output was considered and rejected: it treats the symptom after generation rather than training the generator not to produce the artifact, which is weaker to defend in the thesis.

## What Changes

- Add an optional PostNet-style residual 1D-conv smoothing stack inside `TTSGenerator`, applied to the generator's raw output before it is returned to the training loop / discriminators. Trained end-to-end with the existing adversarial + feature-matching losses — no separate pretraining stage, no encode/decode coupling.
- Gate it behind a new CLI flag `use_postnet` (default `False`), following the same wiring pattern already used for `dwt_j` and `lambda_fm`: `system_inputs.py` schema → `gan_training_main.py` `opt` dict → `initialize_gan.py` → `TTSGenerator` constructor.
- Expose `GAN_USE_POSTNET` in `moabb_pipeline.py`'s GAN config block and thread it through `train_gan()`.
- Record `use_postnet` in the trainer's saved `configuration` dict (same place `lambda_fm`/`lambda_gp` live) so a checkpoint self-describes whether its generator has the PostNet layer — needed by `generate_samples_main.py` / `get_gan_config.py` to reconstruct the right architecture at inference.

## Capabilities

### New Capabilities
- `generator-postnet-smoothing`: optional end-to-end-trained residual conv smoothing of the generator's raw output, to suppress patch-boundary high-frequency artifacts without post-processing or autoencoder coupling.

### Modified Capabilities
(none — no existing capability specs in `openspec/specs/` to modify; this ships as a new capability only)

## Impact

- `eeggan/nn_architecture/models.py` — new `PostNet` module; `TTSGenerator` gains an optional smoothing stage.
- `eeggan/helpers/initialize_gan.py` — thread `use_postnet` into `TTSGenerator` construction.
- `eeggan/helpers/system_inputs.py` — new `use_postnet` CLI flag.
- `eeggan/gan_training_main.py` — `opt['use_postnet']`, recorded in checkpoint `configuration`.
- `eeggan/helpers/trainer.py` — `configuration` dict gains `use_postnet` (read-through, no training-loop logic changes needed since the module lives inside the generator).
- `eeggan/generate_samples_main.py` — must read `use_postnet` from the checkpoint's saved configuration when rebuilding the generator for inference.
- `moabb_pipeline.py` — new `GAN_USE_POSTNET` config var, threaded through `train_gan()`.
- Backward compatible: default `False` reproduces the exact current architecture; existing checkpoints (saved without `use_postnet`) load as `False` via a `.get(..., False)` fallback.
